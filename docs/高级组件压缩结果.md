# 82 个高级组件无损压缩结果

## 1. 本轮处理范围

本轮对 Provider 模板目录中的全部 82 个高级组件形态进行了只读分析和运行时结构压缩：

- 72 个业务模板；
- 10 个布局模板；
- 共 827 个 DOM 节点引用；
- 共 5796 个规范化叶子属性引用。

压缩方式是对不可变 `TemplateNode` 做结构哈希驻留（hash-consing）。组件类型、属性、children 顺序和
条件结构完全相同的子树只保留一个对象，其它模板共享该对象，形成有向无环图。每个原模板 ID、Provider
源文件、数据绑定表、素材、动作和布局契约保持不变。

当前模板注册链路已经使用压缩后的共享 DAG。编译器仍从各模板入口展开和处理普通 `TemplateNode`，
端侧最终收到的仍是原来的 Form 原子组件树。

## 2. 全量压缩结果

| 指标 | 压缩前 | 压缩后 | 减少 | 压缩比例 |
|---|---:|---:|---:|---:|
| DOM 节点定义/引用 | 827 | 416 | 411 | 49.7% |
| 叶子属性定义/引用 | 5796 | 2930 | 2866 | 49.5% |
| 模板 ID | 82 | 82 | 0 | 0% |
| Form 原子组件种类 | 10 | 10 | 0 | 0% |

这里的 49.7% 是真实 DAG 中“节点对象从多少个降到多少个”的结果，不是把嵌套候选的理论节省量直接相加。
父子公共子树重叠时只计算一次，因此不会重复统计收益。

## 4. Battery 结果说明

电池组件是当前重复最明显的业务组：16 个模板包含 131 个节点引用，驻留后只有 37 个唯一节点，减少
94 个，组内压缩率为 71.8%。

检测到的典型公共结构包括：

- `NormalFull`、`ChargingFull`、`LowFull` 的完整根 `Column`；
- 三个 `WideFull` 的完整根 `Column`；
- 三个普通 `Compact` 的完整根 `Column`；
- Full、Hero、WideFull 中复用的环形指标 `Stack`；
- 三个 WideFull 中复用的指标内容 `Row`。

例如 `BatteryOverviewNormalFull@1`、`BatteryOverviewChargingFull@1`、
`BatteryOverviewLowFull@1` 当前的 DOM 值完全相同，因此三个模板入口直接共享同一个根节点对象。它们的
模板 ID 和外部选择语义仍然不同。

`BatteryOverviewNormalHero@1` 与 Full 的外围布局不同，因此没有强行共享完整根树；它只复用内部完全
相同的环形指标子树。这与算法方案中“不要为了压缩把 Full 和 Hero 合成万能模板”的边界一致。

## 5. 精确和近似候选分析

全量分析得到：

```text
精确公共子树类别：64
近似候选对：463
通过当前保守准入门槛的近似候选对：7
```

7 组近似候选主要来自：

- 两组日程模板的 Compact/WideFull 对应结构；
- 应用使用时长的 Full/Hero；
- 耳机盒、左耳、右耳三个形态之间的对应结构。

本轮没有把这 7 组近似候选接入正式渲染链路，原因是：

1. 它们之间存在父子候选重叠，理论节省量不能直接相加；
2. 当前 `.cardtpl` 作者协议没有公共 Pattern 引用语法；
3. 为少量额外收益引入新模板语法，会扩大本轮对编译器和协议的影响面；
4. 精确 hash-consing 已经达到接近 50% 的节点与属性压缩，并且可逐模板证明值完全相同。

因此本轮正式结果选择“全量、精确、无损”的共享 DAG。近似候选保留在分析报告中，后续如果新增受控
Pattern 作者语法，再作为第二阶段压缩输入。

## 6. 等价性保证

`intern_template_definitions()` 对全部 82 个模板执行以下检查：

```text
压缩前 TemplateDefinition.model_dump()
==
压缩后 TemplateDefinition.model_dump()
```

只有值完全一致时才返回压缩目录。哈希命中后还会比较完整节点内容，避免把哈希碰撞误当成同一节点。

因此本轮实现改变的是 Python 对象引用关系：

```text
压缩前：多个模板各自持有值相同的 TemplateNode
压缩后：多个模板引用同一个不可变 TemplateNode
```

而不是改变模板值、组件树或最终 A2UI 输出。

## 7. 渲染比较建议

虽然程序层已经证明 82 个模板定义值相同，仍建议渲染时重点抽样下列类别：

1. Battery：Normal/Charging/Low 的 Full、Hero、Compact、WideFull；
2. Earphone：左右耳、耳机盒、双耳和 WideFull；
3. Calendar：日期、普通日程、带位置和来源的日程；
4. HeartRate：Compact/Full、带图标/不带图标、带更新时间/不带更新时间；
5. Weather：Compact、Hero、Full 及不同主指标；
6. AppUsage：Full、Hero、WideFull、WideHero；
7. 各布局模板至少一张。

比较内容：

- DOM 节点类型和 children 顺序；
- 文本、颜色、尺寸、间距和对齐；
- 可选素材存在与缺失两种情况；
- 必需与可选数据路径；
- Action 的数量、位置和热区；
- 2x2 与 2x4 尺寸。

当前管控配置禁用了 Calendar 和 Earphone Provider。它们已经纳入 82 个模板的压缩统计，但如果通过正常
路由渲染，可能会被管控过滤；做人工对比时需要使用预览/测试入口，或在明确的测试环境中调整管控配置。
